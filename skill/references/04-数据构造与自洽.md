# 04 · 数据构造与自洽

> 本文件解决：**怎么造出一份"在对方校验下自洽"的数据 —— 以及提交时怎么不越线。**
> 适用：需要产出一份能通过服务端校验的记录/报文/文件时。
> ⚠️ 前提：**必须有明确授权**。构造成功 = 真实的业务副作用，且往往**没有删除接口**。

---

## 1. 心智模型：这不是"填字段"，是"解方程组"

要交付的对象通常是**一组互相制约的量**，而不是几个独立字段。

```
点数 × 采样间隔 = 时长
时长 × 平均速度 = 里程
里程 / 时长     = 配速
实际位移 ÷ 步幅 = 步数
围栏几何 + 轨迹 = 围栏内/外点数
打卡点圆 + 轨迹 = 打卡命中数
```

**任意两个确定，第三个就被约束住了。** 所以**不要分别去"设"它们** ——
一旦分别设，必然出现不自洽。

---

## 2. 第一步：把约束收齐（四个来源）

| 来源 | 内容 | 注意 |
|---|---|---|
| **① 格式契约** | 字段、单位、精度、**字符码位** | `pace` 用的是 U+2032/U+2033，不是 ASCII 引号 |
| **② 规则层** | 达标线、区间、有效时段、次数限制 | 常有接口**直接下发**，别去反编译找 |
| **③ 几何** | 围栏多边形、打卡点圆、锚点 | ★ 直接用**对方下发的几何**，别自己拟合 |
| **④ 统计特征** | 噪声自相关、速度方差、点数比例、路线新颖度 | 这一层最容易漏 |

---

## 3. 第二步：把约束分三层（这一步是分水岭）

| 层 | 含义 | 违反的后果 | 例子 |
|---|---|---|---|
| **硬约束** | 不符合直接失败 | 被判无效 / 被拒 | 点在围栏外、时段不对、格式错 |
| **目标** | 必须打中的项 | 拿不到"有效" | 打卡点全过、里程达标、配速在区间 |
| **软约束** | "像不像人" | 可能被判异常 | 自相关、速度起伏、路线新颖度 |

**为什么必须分层**：它们**优先级不同**。
混在一起，就会为了软约束牺牲硬约束（真的发生过，见 §6）。

---

## 4. 第三步：分清自变量与因变量

| 类别 | 内容 | 谁定 |
|---|---|---|
| **自变量** | 路线形状、速度曲线、采样间隔、起起点时间 | **你定** |
| **因变量** | `distance` / `duration` / `pace` / `step` / 内点数 / 外点数 | ★ **被算出来的** |

**正解**：只产出【轨迹】+【时长】，**其余统计量全部从轨迹算出来**。
这样"自洽"不是检查出来的，是**结构上就成立**。

---

## 5. 第四步：闭环标定（两个外环）

因为噪声和加减速会扰动结果，需要闭环：

| 外环 | 解决什么 | 做法 |
|---|---|---|
| **里程标定** | 噪声让累计里程**虚高 15~25%**（锯齿路径 ≥ 直线距离） | **从下往上**逼近（`while km < target: ideal *= 1.015`） |
| **配速标定** | 停走/起跑加速/末段减速把时长抬高 ⇒ 配速偏慢 | 按 `实测配速/目标配速` 缩放速度，迭代 ≤5 次，3% 内停 |

**为什么配速外环必需**（不是装饰）：

```text
只标里程 ⇒ 上报配速 8′12″（目标 6′12″）   ← 整整慢两分钟
```

### ★ 铁律：迭代中被比较的基准必须不变

踩过的坑：一个随机因子原本在**每次迭代里重掷** ⇒ **标定在追一个移动的目标** ⇒
永远收敛不了（实测配速漂到 `7′17″` 还稳不下来）。
**修法只是把它移出循环** —— 一行改动决定收敛与不收敛。

---

## 6. 第五步：多目标择优（不能单目标最优）

真实冲突（实测）：

```text
为了避免被判"白噪声"，加了一道平滑
⇒ 它把"绕去打卡点"的尖峰也当噪声抹平了
⇒ 4/5 号种子：自相关很漂亮（软约束✅） 但打卡点一个都没走到（目标❌）
```

**修法**：把"必打点是否全命中"排到择优函数**第一位**。

```python
return (h < need,        # ① 没全中 最差          ← 目标 ∨ 硬约束
        outer > 0,       # ② 有外点
        clamped > 0,     # ③ 有越界被拉回的点
        h * -1,          # ④ 命中越多越好
        clamped + outer) # ⑤ 越界+夹取总量          ← 软约束最后
```

**这条顺序就是"分层优先级"在代码里的样子。**

> **每加一道"让数据更自然"的工序，都要回头确认它有没有把"让数据更对"的工序毁掉。**
> 这类冲突**只能靠多目标择优解决**。

### 结构兜底优于事后检查

当几何很难搞（凹多边形：噪声一抖就出界），**兜底用内切圆** ——
**圆一定在多边形内 ⇒ 结构上保证 0 外点 / 0 夹取**。

> **能用"结构上不可能"解决的，不要用"检查会不会发生"解决。**

## 7. 统计特征：这里有一个反直觉的坑

### 三种已经确认会死的形态

| 死法 | 真实样本 | 反应 |
|---|---|---|
| **站着不动刷点** | 6143 个点**坐标完全相同**，里程仅 0.68 km | 判无效 |
| **步距与位移对不上** | 0.35 km / 92 步 = 步幅 **3.8 m**（人不可能） | 不自洽，留把柄 |
| **匀速直线** | —— | 匀速是**最典型的判据**（真人没有平坦速度曲线） |

### ★ AR(1) 噪声救不了自相关

反作弊会查**相邻点位移的 lag-1 自相关**（阈值约 0.3），低了就判"白噪声=伪造"。

**第一反应**（错的）：把噪声做成相关的（AR(1)，`noise[i] = ρ·noise[i-1] + ε`），加大 ρ。

**实测**：`ρ=0.047 → 0.05`、`ρ=0.071 → 0.05` —— **几乎没动**。

**为什么**：

> **相邻两点的位移 = AR(1) 噪声的一阶差分。**
> 而对 AR(1) 做差分，**结果本身就是白噪声**。

**所以调的不是"一个不够大的量"，是"一个方向错的量"。**

**正解：复刻对方的预处理。** 真实客户端上传前会做**卡尔曼滤波** ——

> 真人轨迹平滑，**不是因为 GPS 准，是因为客户端平滑过**。
> 想产出同分布的数据，就要走**同一条流水线**。

实现要点：一维卡尔曼逐轴；`q` 很小（信任匀速 ⇒ 越平滑）；
`r` 用候选集（`2.5e-9 / 4e-9 / 6e-9`）取分最高 —— **它们不是物理量，是平滑强度旋钮**。

**效果**：不加平滑 `0.05~0.28` ❌ → 加平滑 **`0.60~0.91`** ✅（3 场景 × 5 种子）。

**另一个幅度坑**：噪声幅度**不能用固定绝对值**，要**相对每步位移**。
固定 1.6 m 在步长 13 m 时被运动淹没；步长很小时又主导序列 ⇒ 自相关掉到 0.221。

## 8. 覆盖与代价：把"随机"量成一个数字

评估一个"随机化/挑战"到底是不是防线，**必须同时算两个数**：

| 量 | 问什么 | 怎么得到 |
|---|---|---|
| ① **组合空间** | 有几种可能？ | **枚举观测到饱和**（看集合何时不再增长） |
| ② **覆盖代价** | 把**所有**可能都满足，要付出什么？ | 求**最优策略**的代价（顺序会影响它） |

**常见错法只算①**："有 45 种组合，猜中概率只有 1/45，很安全。"
**错在**：对手的策略是"**一次全覆盖**"，不是"猜一个"。

**实测的两个数**：

```text
候选项 10 个、每次给 2 个 ⇒ 组合空间 C(10,2) = 45
串起全部候选圆（最近邻）≈ X
而"达标"本身只要              Y，且 X 显著小于 Y
```

> ★ **判据**：**如果"覆盖全部可能"的代价，比"达标"本身还低，这道防线为 0。**
>
> 而且这条路线在数据上**毫无异常** —— 长度合理、配速正常、点分布自然。

**饱和判定的三条要求**（容易偷懒）：
① 看到**增长速度下降**（不只是"停止增长"）；
② **换时间段复测**（跨时段是否稳定）；
③ 记录**总次数**（枚举成本本身也是代价）。
> 没做全的，就如实标注"**结论作用域未验证**"，别把话说满。

### 给防守方（报告里最有用的三行）

| 动作 | 抬高的是 |
|---|---|
| **限制读取频率** | 枚举成本（改一行就能做） |
| 把池子做大、做动态 | 组合空间 + 稳定性 |
| 让"覆盖全部可能"的代价**高于**达标线 | 覆盖代价（最根本） |

## 9. 提交与回读

### 9.1 写操作纪律

| 机制 | 作用 |
|---|---|
| **默认 dry-run** | 直接跑脚本不发请求，只打印将发送的内容 |
| **显式 `--live` 二道闸** | 真正提交必须显式加参数 |
| **单发，不批量** | 脚本层面也不提供循环 |
| **不重试传输层** | 读可重试；**写不行** —— 重试可能产生重复记录 |
| **写台账** | 每次记时间/目标/结果 id |

> "不重试"是为了不产生重复记录；"写台账"是为了万一重放了还能对上账。**两者缺一，出事说不清。**

### 9.2 回读看什么

| 看什么 | 为什么 |
|---|---|
| ❌ `code:0` | 只说明"记录建了"（无效记录也是 `code:0`） |
| ❌ 响应里有没有回显 | **回显是展示行为，判定是业务行为** |
| ✅ **`status` / 判定项** | 逐项说明哪条规则过没过 |
| ✅ **副作用指标**（如学期进度是否变化） | "这条记录算不算数"的最终确认 |

### 9.3 副作用披露（必做）

把**所有写操作**列成表（id / 状态 / 用途 / 影响 / 清理方式），
并**请对方清除**（如果系统没有删除接口，那就只能由他们处理）。

> **授权测试里，"我做了什么"必须比"我发现了什么"说得更清楚。**
> 发现可以商榷，副作用不能商榷。**不清就是留了一条假记录。**

```text
[ ] 约束收齐了四个来源？（格式/规则/几何/统计）
[ ] 分了硬约束 / 目标 / 软约束，并且择优顺序与之一致？
[ ] 只产出因变量的"源头"，其余全部算出来的？
[ ] 两个外环都标定了？迭代基准是常量？
[ ] 换多个随机种子仍稳定？（否则只是运气）
[ ] 统计特征对齐了对方的**预处理流水线**（而不是在出口拗形状）？
[ ] 若涉及"随机化防作弊"：算出组合空间 + 覆盖代价，并拿目标硬约束当尺子？
[ ] 写操作：dry-run / 单发 / 不重试 / 台账？
[ ] 回读看的是判定语义，不是"创建成功"？
[ ] 副作用清单 + 清理方式 + 请求足迹？
```
